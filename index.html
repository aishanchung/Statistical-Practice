2. V2 Enriched Trip Master 資料架構

M06B + M05A + M03A + VD + Weather + Calendar / Holiday
↓
V2 Enriched Trip Master

V2 延續 V1 的旅次層級設計， 一列仍然代表一筆通過研究瓶頸的 M06B trip。 VehicleID、OD、TripInformation、TripLength 等旅次資訊全部保留。

交通狀態欄位的重複是預期結果： 同一 Route / Direction / Time5 內的多筆 M06B trip， 會共享相同的 M03A、M05A、VD、Weather 與 Calendar context。 因此同一個 VD speed 或 occupancy 可能在多筆 trip row 中重複， 這不是 duplicate error。
建模層級： MASTER_V2 是 trip-level 資料， 不直接將每一筆 trip 視為獨立的交通狀態 observation。 後續壅塞預警會另建 MODEL_5MIN_V1， 聚合為「一列 = Route × Direction × Time5」。

加權速度

Vt = Σ( Speedk,t × Volumek,t ) / Σ Volumek,t

M05_Speed_Weighted 為各車種速度依交通量加權後的 綜合站間速度。

D. M03A — 單一 eTag 門架 5 分鐘交通量

M03A 以研究瓶頸 eTag 門架為單位， 提供每 5 分鐘、依車種區分之通過交通量。 V2 以 Time5 = M03_Time5 進行 many-to-one left join。

欄位 單位 / 型態 定義
M03_GantryID string 研究瓶頸所使用的 eTag 門架。
M03_Volume_31 / 32 / 41 / 42 / 5 veh / 5min 五種車種在該門架、該 5 分鐘的通過交通量。
M03_Volume_Total veh / 5min 五車種交通量合計；五類資料完整時才計算。
M03_Volume_OwnType veh / 5min 該筆 M06B trip 所屬車種在相同 5 分鐘的 M03A 流量。
M03_Matched boolean 該 trip 的 Time5 是否成功匹配 M03A。
E. VD — 局部交通狀態 snapshot
時間定義： VD 不是五分鐘平均值。 本研究建立 5 分鐘 Target Time， 並使用距離該 Target Time 最近、且 |LagMin| ≤ 4 分鐘 的一分鐘 VD observation 作為該時間格點的 snapshot。 Target Time 與 DataCollectTime 均以台灣本地時間解讀。

Sensor-specific 欄位

欄位型態 定義
VD_*_Speed 該 VD 在該 Time5 的有效 snapshot speed（km/h）。
VD_*_Occupancy 該 VD 各有效車道 occupancy 的平均值。
VD_*_LagMin Target Time − 實際 DataCollectTime，單位為分鐘。
VD_*_Status 原始 VD Status；1 / 2 / 3 視為明確異常。
VD_*_Observed 該 sensor / Time5 是否存在原始 snapshot。
VD_*_Valid Speed 可用、|Lag| ≤ 4 分鐘且無明確異常 Status 時為 TRUE。

Dynamic Primary VD

每個 Time5 會從當下 ValidSnapshot = TRUE 的 VD 中，選擇距研究瓶頸 eTag 門架最近者作為 Dynamic Primary VD。 因此 Primary VD 並非永遠固定同一支 sensor； 若最近 sensor 當下無有效資料，可使用下一支距離較近的有效 sensor。

欄位 定義
VD_PrimarySensorID 該 Time5 所選擇的最近有效 VDID。
VD_PrimarySpeed Dynamic Primary VD 的 speed。
VD_PrimaryOccupancy Dynamic Primary VD 的 occupancy。
VD_PrimaryLagMin Dynamic Primary VD 與 Target Time 的分鐘差。
VD_PrimaryValid 該 Time5 是否至少存在一支有效 VD；若存在，Primary 即為有效。

為什麼不是 100% 都有 VD？

MASTER_V2 以 M06B trip 為主表，因此只要某個 trip 的 Time5 在 VD 資料中沒有任何目標 sensor observation， 該 trip 仍會由 LEFT JOIN 保留下來，但 VD 欄位會是 NA。 另外，「有 observation」不代表一定「有效」。 有些 VD observation 因為與 Target Time 相差超過 4 分鐘、 沒有可用的 sensor speed，或設備 Status 明確異常， 會保留 QC 紀錄但不作為有效 VD traffic state。 因此： VDObservationPct 通常略高於 ValidVDPct， 而不到 100% 並不是 merge 失敗。

5.0.3 VD sensor availability

N3 南向的 sensor 並非全期間固定同一組。 例如 VD-N3-S-62.008-M-LOOP 在目前資料中只出現到 2024-03-25， 而 VD-N3-S-64.500-M-RS 與 VD-N3-S-66.020-M-LOOP 自 2024-04-11 起出現。 因此程式使用 Dynamic Primary VD，而不假設兩年間永遠固定同一支 sensor。

5.0.4 VD time / stale QC

多數 sensor 的絕對時間差中位數約 1–2 分鐘， 95th percentile 約 2–3 分鐘。 超過 ±4 分鐘者標記為 stale，不作為有效 VD traffic state。 QC 另保留極端時間差及 speed > 180 km/h 的 REVIEW 清單。

5.1 QC 檢查原則

本研究將 QC 問題區分為三類：

類型 定義 處理方式
PASS 檢查結果符合資料定義， 未發現異常。 保留原始資料。
Structural NA 欄位在該筆紀錄本來就不適用， 因此產生 NA。 保留 NA， 不補值、不刪除。
REVIEW 數值較極端， 但不能直接判定為錯誤。 回查原始路徑與時間， 再決定是否處理。

5.2 Missing Value 檢查

大部分核心欄位皆無缺失。 Missing value 主要集中於假期名稱類欄位， 以及少量由資料定義自然產生的欄位。

欄位 QC 判定 原因 處理方式
HolidayName Structural NA 非連假日期本來就沒有 HolidayName。 保留 NA。
PreLongHolidayName Structural NA 只有連假前一天才有值。 保留 NA。
StandaloneHolidayName Structural NA 只有單日國定假日才有值。 保留 NA。
HolidayEventName / HolidayEventStart / HolidayEventEnd Structural NA 只有落在 Holiday Event Window 的日期才具有假期事件資訊。 保留 NA。
HolidayDayIndex Structural NA 只有正式假期期間才有 Holiday Day Index。 保留 NA。
重要： 上述 NA 並不代表資料遺失， 而是該欄位在一般日期 不適用（Not Applicable） 。 因此不應使用平均數、 眾數或其他方式進行 imputation。

四個方向共有少量 M05_Speed_Weighted 缺值。

路段方向 NA 筆數 NA 比例 QC 結果

檢查結果顯示， 所有 M05_Speed_Weighted = NA 的紀錄皆同時滿足：

M05_Volume_Total = 0

因加權速度定義為：

Vt(w) = Σ( Speedk,t × Volumek,t ) / Σ Volumek,t

當總交通量為 0 時， 分母為 0， 因此加權速度無法定義。

處理方式： 保留 M05_Speed_Weighted = NA。 不可將其補為 0， 因為速度 0 會被誤解為嚴重壅塞。

VehicleType = 0 UNKNOWN 保留旅次，車種視為 UNKNOWN
TripLength > 500 km EXTREME 保留並建立 flag
Exact Duplicate PASS 0 筆，不需刪除
V1 Core Master — QC PASS

V1 Core Master 可進入正式 Exploratory Data Analysis（EDA） 與後續 5-minute Modeling Dataset 建置階段。
