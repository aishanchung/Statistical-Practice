2. V1 Core Master 資料架構

M06B + M05A + Weather + Calendar / Holiday
↓
V1 Core Master

Master Data 保留原始旅次層級資訊， 因此不會失去 VehicleID、OD、 TripInformation 等資訊。

重要： Master Data 並不是最終的 5-minute modeling dataset。 後續壅塞預警模型會另外從 Master 聚合成「一列 = 一個 5 分鐘時段」， Master 本身永久保留。

5. Data Quality / QC

在正式進行 EDA 與建模前， 先針對四個 V1 Core Master 進行資料品質檢查。 QC 原則為： 先標記、再判斷，不因極端值自動刪除資料。

QC Status PASS

未發現需要大規模刪除的系統性資料錯誤。

Master Files 4

N3 / N5 × 南北方向。

Exact Duplicate 0

四個方向皆未發現完全重複旅次。

QC Decision KEEP

目前不進行大規模 row deletion。

5.1 QC 檢查原則

本研究將 QC 問題區分為三類：

類型 定義 處理方式
PASS 檢查結果符合資料定義， 未發現異常。 保留原始資料。
Structural NA 欄位在該筆紀錄本來就不適用， 因此產生 NA。 保留 NA， 不補值、不刪除。
REVIEW 數值較極端， 但不能直接判定為錯誤。 回查原始路徑與時間， 再決定是否處理。

5.2 Missing Value 檢查

大部分核心欄位皆無缺失。 Missing value 主要集中於假期名稱類欄位， 以及少量由資料定義自然產生的欄位。

欄位 QC 判定 原因 處理方式
HolidayName Structural NA 非連假日期本來就沒有 HolidayName。 保留 NA。
PreLongHolidayName Structural NA 只有連假前一天才有值。 保留 NA。
StandaloneHolidayName Structural NA 只有單日國定假日才有值。 保留 NA。
HolidayEventName / HolidayEventStart / HolidayEventEnd Structural NA 只有落在 Holiday Event Window 的日期才具有假期事件資訊。 保留 NA。
HolidayDayIndex Structural NA 只有正式假期期間才有 Holiday Day Index。 保留 NA。
重要： 上述 NA 並不代表資料遺失， 而是該欄位在一般日期 不適用（Not Applicable） 。 因此不應使用平均數、 眾數或其他方式進行 imputation。

5.3 M05_Speed_Weighted 缺值

四個方向共有少量 M05_Speed_Weighted 缺值。

路段方向 NA 筆數 NA 比例 QC 結果
N3 大溪－龍潭 北向 1,952 0.0043% PASS
N3 大溪－龍潭 南向 3,655 0.0079% PASS
N5 坪林－頭城 北向 10,335 0.0466% PASS
N5 坪林－頭城 南向 4,401 0.0194% PASS

檢查結果顯示， 所有 M05_Speed_Weighted = NA 的紀錄皆同時滿足：

M05_Volume_Total = 0

因加權速度定義為：

Vt(w) = Σ( Speedk,t × Volumek,t ) / Σ Volumek,t

當總交通量為 0 時， 分母為 0， 因此加權速度無法定義。

處理方式： 保留 M05_Speed_Weighted = NA。 不可將其補為 0， 因為速度 0 會被誤解為嚴重壅塞。

5.4 VehicleType = 0

原始 M06B 中發現極少數 VehicleType = 0 紀錄。

路段方向 VehicleType = 0 QC 結果
N3 北向 103 PASS
N3 南向 69 PASS
N5 北向 36 PASS
N5 南向 37 PASS

總計： 245 筆

這些紀錄的 M05_Speed_OwnType 與 M05_Volume_OwnType 皆為 NA。

原因是目前 M05A 車種分類僅包含： 

31 = 小客車
32 = 小貨車
41 = 大客車
42 = 大貨車
5  = 聯結車
處理方式： 將 VehicleType = 0 視為 UNKNOWN。 保留該筆旅次， 不因車種未知而刪除整筆資料。

5.5 TripLength 極端值

第一輪 QC 將 TripLength > 500 km 標記為 REVIEW， 進一步檢查其旅次時間與 TripInformation。

路段方向 > 500 km 比例 最大 TripLength
N3 北向 5,899 0.0131% 928.65 km
N3 南向 6,738 0.0146% 987.00 km
N5 北向 204 0.00092% 899.10 km
N5 南向 173 0.00076% 899.10 km

進一步依不同門檻統計：

TripLength 筆數
> 500 km 13,014
> 600 km 6,948
> 700 km 1,650
> 800 km 170
> 900 km 3

進一步檢視極端旅次之 DetectionTime、 TripDuration 與 TripInformation， 可觀察到其路徑通常包含大量連續門架， 並具有相對應的長旅次時間。

因此目前沒有足夠證據將 TripLength > 500 km 視為錯誤資料。

QC Decision： Extreme but internally coherent trip。 保留原始資料， 但後續分析可建立： IsVeryLongTrip = 1(TripLength > 500) 進行 sensitivity analysis。

5.7 QC Scripts

QC 分為兩階段：

程式 用途
qc_master_v1.py 第一輪 QC： Missing Value、 數值範圍、 時間一致性、 M05A / Weather / Calendar merge、 Gantry、 Weighted Speed 等基本檢查。
qc_followup_v1.py 第二輪 QC： Weighted Speed NA、 VehicleType=0、 TripLength > 500 km 與 Exact Duplicate 深入檢查。

5.8 Final QC Decision

綜合 Missing Value、 時間一致性、 Merge、 M05A、 Weather、 Calendar、 TripLength 與 Duplicate 檢查後， V1 Core Master 未發現需要進行 大規模資料刪除的系統性錯誤。
