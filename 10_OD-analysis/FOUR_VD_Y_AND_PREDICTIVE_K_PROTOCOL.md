# OD 分群與四站 VD 壅塞 Y：正式研究設定（2026-11-04）

> **決策紀錄：** 本專案後續用「交流道間候選」的四站 VD 定義主要壅塞標籤 `Y_t`。五站全範圍版本僅作歷史對照或另行宣告的敏感度分析，**不得**在主分析中混用。此決策取代先前「五站作為正式 Y」的草案。

## 1. 範圍、資料及四站權重

- 研究對象：國道三號龍潭—大溪**北向**路段；OD `V2_LITE_WEATHER/V2_parts` 已依研究路段過濾。
- 研究前提：龍潭與大溪交流道之間沒有中途可進出交流道；本研究 OD 旅次均完整通過研究路段。因此**不再**二次篩選 OD 是否通過路段，也**不再**區分「完整通過／部分通過」OD。
- 對應截圖的四站權重（「交流道間候選」，代表區間按相鄰 VD 里程中點切分，再按代表長度正規化）：

| VD 里程／站 | 正式分析權重 `w_j` | 用途 |
| --- | ---: | --- |
| K69.510 | 0.0417 | 納入 |
| K65.990 | 0.4600 | 納入 |
| K63.990 | 0.3600 | 納入 |
| K61.670 | 0.1383 | 納入 |
| K61.000 | **0** | **不納入正式 Y**；五站全範圍僅可做敏感度分析 |

四個非零權重總和為 1.0000。權重來自當前網站「62–68K 交流道間候選」表；該 62–68K 是名義研究範圍的**候選邊界**，並非已核實的交流道精確里程。正式發表前仍須核對交流道實際里程與所用 VD 位置；目前不自行更改這組已確認的候選權重。

## 2. `Y_t` 的正式計算方式

在同一個五分鐘時間格 `t`，四站速度 `V_{j,t}` 單位 km/h：

`L_{j,t} = 1(V_{j,t} < 40)`。令 `O_t` 為當下有有效速度（`Speed >= 0` 且非 NA）的 VD 集合；**主分析採「可用站權重重正規化」**：

`C_t^(w) = [Σ_{j∈O_t} w_j L_{j,t}] / [Σ_{j∈O_t} w_j]`（`|O_t| >= 1`）。

當四支都有值時，這與原本 `Σ_{j∈4VD} w_j L_{j,t}` 完全一致。

三分類：

```
Y_t = 0    if C_t^(w) = 0                  （未觀測到四站壅塞）
Y_t = 1    if 0 < C_t^(w) < c              （局部壅塞）
Y_t = 2    if C_t^(w) >= c                 （大範圍壅塞）
```

- **`c` 尚未由團隊最終確認**；不可暗中將 0.5 當成已核准的定案。進行正式選 K 前，以 2024 年訓練資料與交通解釋選定主要 `c`，並固定後評估 2025；可對 `c = 0.25, 0.50, 0.75` 另做標示清楚的敏感度分析（僅為候選值）。
- **2026-11-04 使用者已明確決定：只要有任何一支 VD 有效就計算 Y，不設最低三站／75% 權重覆蓋門檻；只有四站全部無效才 `Y_t = NA`。** 權重依當下有效站重新正規化；無效速度不可當成 0 km/h、也不可當成未壅塞。僅一支有效站時，`C_t^(w)` 只會是 0 或 1（`Y=0` 或 `Y=2`），此時空間代表性較低，必須保留 `n_valid_vd`、`weight_coverage`、`used_partial_vd` 以供敏感度分析。
- `V3_Y_5MIN.parquet` 使用此可用站定義；「四站全有效的比例」仍保留於資料品質報表，**不是正式 Y 缺失率**。如另行比較單站短補／全站短補的敏感度版本，須在輸出版本明確標註，不能默默替換主要 Y。
- 必須記錄輸出標籤使用的版本（四站及權重、`c`、VD 速度來源、缺失方案、時區／五分鐘格），避免各模型使用不同 `Y`。
- 若須預測「是否發生大範圍壅塞」，定義二元輔助標籤 `Y_t^severe = 1(Y_t = 2)`；三分類 `Y_t` 原始定義保留。

## 3. OD 分群與五分鐘解釋變數

- 分群單位是一組 `(GantryO, GantryD)`，**不是**每一筆旅次；OD 事先已通過研究路段篩選。
- 2024 年資料建立 OD 分群；2025 年只用來做未來時間的評估。2024 年至少 100 筆旅次的 OD 作主要分析（前次全量結果：3,103 組；涵蓋 2025 年 97.51% 旅次）。未達門檻及新出現的 OD 記為 `OTHER`，**不得丟掉其車流量**。
- 對每個候選方法 `m` 及群數 `K`，將 OD 標籤固定為 `C_i^(m,K)`，聚合五分鐘車流：

  `X_(m,K,g,t) = Σ_i 1(C_i^(m,K)=g) 1(T_i 在五分鐘格 t)`，`g = 1..K, OTHER`。

- 所有車輛已知完整通過研究路段，**不需要**再做「是否經過哪支 VD」的 OD 路徑篩選。五支 VD 的速度本來就可對應不同時間的車隊；OD 的 `T_i` 必須採明確一致的「路段代表通過時間」。
- 現有 `BottleneckTime` 為回溯型資訊，包含事後才能確定的完整 OD；**不得直接當作即時預測時可用的未來資訊**。`DetectionTimeD` 是完成旅次時間的候選代理，也須確認實際資訊可用時點。先區分「回溯關聯分析」與「真正可部署的提前預測」。
- 輸入 5 分鐘群組數量時，可同時嘗試過去 5／15／30／60 分鐘的落後項或滾動量，所有模型必須使用相同時間對齊／可用資訊規則；不要利用 `t` 之後資料預測 `Y_(t+h)`。
- 若總量 = 各群（含 OTHER）總和，線性模型不可在沒有約束的情況下同時放進「總量」與每群量，避免完全共線；可用各群數量（不另加總量）或總量搭配 K−1 個占比。

## 4. 如何選對壅塞預測最好的 `K`

### 4.1 主實驗：四種方法 × 四種群數

保持相同訓練樣本、相同 `time_vehicle` 特徵（先不加入距離或流量，以免混淆 K 效果），一共 16 組：

| 方法 `m` | 要測試的 K |
| --- | --- |
| K-means | 2, 3, 4, 5 |
| K-medoids | 2, 3, 4, 5 |
| GMM（對角共變異數） | 2, 3, 4, 5 |
| Sparse K-means | 2, 3, 4, 5 |

第二階段再固定相同切分，比較 `time_vehicle_distance` 特徵；勿把「不同特徵組合」與「不同群數」的效果混為一談。

### 4.2 固定下游模型、只改分群方案

以下所有模型共同使用相同時間、月分／假日、天氣、VD 歷史等基準變數及相同分類器與調參預算；唯一不同的是 OD 欄位：

| 模型 | OD 輸入 | 用途 |
| --- | --- | --- |
| B0 | 無 OD 變數 | 基準 |
| B1 | OD 總車流（可納入落後量） | 驗證「OD 資訊」本身是否有幫助 |
| B2(m,K) | 各群 `C1..CK` + `OTHER` 的車流 | 驗證「OD 分群」的增額價值 |

`B0/B1/B2` 僅為此處**比較版本名稱**，不要與已訂的 VD `M0/M1/M2/M3` 標籤混淆。

### 4.3 正確的時間切分／防止資料洩漏

1. **2025 全年資料先保留為最終測試集**，不得用 2025 反覆選 K、特徵、`c` 或預測模型設定。
2. 在 2024 年內做依時間向前的訓練／驗證。嚴格版本應在**各驗證折的訓練期內**重新估計 OD 特徵、標準化參數、OD 分群、缺失補值規則及預測模型；不用該折驗證期的資訊建立當折分群。
3. 各方法/K 在相同驗證折比較；完成選擇後，使用完整 2024 年重新訓練，最後僅在 2025 年報告一次外部測試績效。
4. OD 旅次的目的地及完整路程若尚未實時得知，只能做事後／完成旅次特徵；做真正提前預測時需使用到預測時點已知的資訊。

### 4.4 評分與明確的選 K 準則

- **主要指標預先宣告**：若研究重點是大範圍壅塞預警，建議用驗證期 `Y=2` 的 **PR-AUC（Average Precision）**；若主要研究三種壅塞程度的整體辨識，則改以 **macro-F1** 為主要指標。不可看完結果再任意變更主要指標。
- 同時報告 `Y=2` 的 Recall、Precision、F1、誤報率，以及三分類 confusion matrix / macro-F1。比較每一個候選對 B1 的增額改善，並按連續壅塞事件／月份檢查穩定性。
- 分群檢查：各群 OD 占比、各群**實際旅次占比**、有車流的五分鐘格數、穩定性 ARI、群組解釋性；避免 1 個極小群造成看似漂亮但不穩定的結果。
- **選 K 原則**：先取 2024 時序驗證之主要指標最好、且較 B1 有穩定改善的組合；若多組差異落在驗證不確定性之內（例如 1-SE 規則），選較小 K／較易解釋者。以 2025 測試確認，不為追求 2025 分數重新選 K。
- 不以 Silhouette、ARI、GMM BIC 直接宣布「預測最佳 K」。這些屬於**分群本身的診斷**，並非下游預測績效。

### 4.5 結果報告最低欄位

`method, feature_set, K, fold, n_OD, min_OD_share, min_trip_share, silhouette, stability_ARI, B1_metric, B2_metric, delta_vs_B1, severe_recall, severe_F1, macro_F1, test_period, Y_version, c, lag_spec`。

正式版應同時呈現四種方法 × K=2..5 的交叉表，標出 2024 驗證選出的方案，以及其**唯一一次** 2025 測試結果。

## 5. 目前程式做到哪裡／尚缺什麼

- `od_clustering.py` 現有 `method_scores.csv` 已可比較所有分群方法 × K 的**探索性指標**。
- **目前 `od_cluster_labels.csv` 與可選 `five_min_bottleneck.csv`／`five_min_completed.csv` 只對探索性選出的單一候選模型輸出**。因此現有檔案還不能直接比較 16 組下游預測結果；後續需為每一候選 `m,K` 輸出 OD 標籤，再對同一來源旅次彙總各組五分鐘流量。
- 仍需整合四站 VD 的 5 分鐘速度、缺值方案與最後確認的 `c`，才可以真正計算 `Y_t` 並做 B0/B1/B2 評估。
- 在未執行上述 2024 時序驗證與 2025 測試前，**不得**宣稱已找到「預測最佳 K」；現有 K=2 僅代表分群探索性評分最佳。
